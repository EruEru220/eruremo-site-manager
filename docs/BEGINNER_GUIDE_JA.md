## 1. このツールは何をしているの？

`eruremo_SiteManager.html` は、**「ホームページを作る機械」**です。

```
┌─────────────────────────────────────┐
│  eruremo_SiteManager.html           │  ← ① あなたが編集する道具
│  （編集ツール・2MB）                 │     ダブルクリックで開く
└──────────────┬──────────────────────┘
               │「⬇ ホームページを保存」を押すと…
               ▼
┌─────────────────────────────────────┐
│  index.html                         │  ← ② できあがるホームページ
│  （完成したホームページ）             │     これを人に見せる
└─────────────────────────────────────┘
```

大事なポイント：**この2つはまったく別のファイルです。**

| | `eruremo_SiteManager.html` | `index.html` |
|---|---|---|
| 役割 | 編集する**道具** | 完成した**作品** |
| 誰が見る | あなただけ | インターネットのみんな |
| 中身 | 編集画面のUI ＋ 作品のひな形 ＋ 初期データ | 作品そのもの |
| 作られ方 | 最初からある | ボタンを押すたびに作り直される |

**`eruremo_SiteManager.html` を人に渡してはいけません。**
中には編集用の設定（プレゼントの合言葉など）が入っています。人に見せるのは `index.html` だけです。

## 2. `eruremo_SiteManager.html` の中身

このファイルは 2,016 行あります。でも、実は**そのうち 2 行だけで全体の 95%** を占めています。

| 行 | 中身 | 大きさ |
|---|---|---|
| 1〜398行 | 編集画面の見た目（HTMLとCSS） | 小さい |
| **399行目** | **`TEMPLATE`** = 完成サイトの**ひな形** | 約 205,000 文字 |
| **400行目** | **`DEFAULT_DATA`** = **お手本の初期データ**（写真15枚入り） | 約 1,792,000 文字 |
| 402〜2013行 | 編集ツールの頭脳（JavaScript） | 小さい |

**用語**

> **HTML**（エイチティーエムエル）… ページの「骨組み」を書くための言葉。「ここは見出し」「ここは写真」を指定します。
>
> **CSS**（シーエスエス）… 「見た目」を決める言葉。色・大きさ・並べ方を指定します。
>
> **JavaScript**（ジャバスクリプト）… ページを「動かす」ための言葉。ボタンを押したときの反応などを書きます。
>
> **Base64**（ベースろくじゅうよん）… 写真などのデータを、**文字だけで表す方法**。
> 写真をそのまま文字にできるので便利ですが、**元のデータより約33%大きくなります**。
> 399・400行目が異常に長いのは、これが理由です。

## 3. `index.html` の役割

「⬇ ホームページを保存」を押すと、次のことが起きます。

```
あなたの編集内容（DATA）
    ↓
399行目の TEMPLATE（ひな形）を用意
    ↓
ひな形の中の 8 個の「差し込み口」に値を入れる
    ├─ __PAGE_TITLE__   → サイトの名前
    ├─ __PAGE_DESC__    → サイトの説明
    ├─ __THEME_COLOR__  → テーマカラー
    ├─ __OG_EXTRA__     → SNS用の情報
    ├─ __TWITTER_EXTRA__→ X用の情報
    ├─ __FAVICON__      → タブのアイコン
    ├─ __JSONLD__       → Google向けの情報
    └─ __SITE_DATA__    → あなたのデータ全部
    ↓
index.html が完成 → ダウンロード
```

できあがった `index.html` は、**それ1つだけで完全に動きます**。
CSSも、JavaScriptも、写真も、全部この1ファイルの中に入っています。
インターネットにつながっていなくても、ダブルクリックすれば表示されます。

## 4. 編集した内容はどこに保存されているの？

**あなたが使っているブラウザの中**（`localStorage` という場所）です。

> **localStorage**（ローカルストレージ）… ブラウザが用意している小さな保管庫。
> **そのブラウザ・そのファイルの場所** に結びついています。

保管庫の名札：`elremo_editor_data_v9`

### ⚠️ ここが一番大事です

**次のことをすると、編集内容は予告なく全部消えます。**

| してしまうと消えること | なぜ |
|---|---|
| ブラウザの「閲覧履歴データの削除」で「Cookieとサイトデータ」を消す | 保管庫ごと消えます |
| シークレット／プライベートウィンドウで使い、閉じる | 最初から保存されていません |
| 別のパソコン・別のブラウザで開く | 保管庫は共有されません |
| **HTMLファイルを別のフォルダに移動する** | 「場所」が変わると別物とみなされます |
| 写真を入れすぎて容量オーバー | 保存に失敗します（画面に「保存できません」と出ます） |

さらに、**Ctrl+Z（元に戻す）の履歴は、ページを再読み込みすると消えます。**

### だから：`.json` の書き出しが命綱です

> **JSON**（ジェイソン）… データを文字で書き表すための形式。
> `{"名前": "える", "色": "青"}` のように、コンピュータが読みやすい形でデータを保存します。

**メニュー → 「💾 プロジェクトを書き出す（.json）」**

これで `elremo-project.json` がダウンロードされます。
これが**あなたの編集内容の完全なバックアップ**です。

**おすすめの習慣：**

1. 作業を始める前に1回、書き出す
2. 大きな変更（写真の一括追加、リセット、URL方式への変換）の**前**に書き出す
3. 作業を終えるときに1回、書き出す
4. ダウンロードフォルダから、日付をつけたフォルダに移して保管する
   （例：`バックアップ/2026-08-05/elremo-project.json`）

**⚠ 注意**：この `.json` には、**プレゼントの合言葉が「そのまま読める形」で入っています。**
`index.html` には暗号化されて入るので安全ですが、`.json` は**人に渡さないでください。**

## 5. なぜ写真が問題なの？

いま、写真は **Base64 という方法で HTML の中に文字として直接入っています。**

```
写真（実データ 100KB）
    ↓ Base64に変換
"data:image/jpeg;base64,/9j/4AAQSkZJRgABA..."（約 133KB の文字列）
    ↓
編集データの中に入る
    ↓
localStorage にも、index.html にも、.json にも、全部この文字列が入る
```

いまのお手本データだけで、**写真15枚＝約1.3MB** を使っています。
localStorage の上限は**約5MB**なので、**すでに4分の1を使っている**状態です。

写真を数十枚追加すると、次のことが起きます：

- 自動保存が失敗する（「保存できません」）
- `index.html` が数MBになり、**ホームページの表示が遅くなる**
- 編集画面のプレビューも遅くなる

### 解決策：写真を「別の場所」に置いて、URLで参照する

```
【いまのやり方】                【これからのやり方】
写真そのものを                  写真は別の場所に置いて
HTMLの中に入れる          →     住所（URL）だけを書く

index.html = 数MB               index.html = 数十KB
```

この「別の場所」が **Cloudflare R2** です。

## 6. これから使うサービスの説明

### Git（ギット）

> **Git**… ファイルの変更履歴を記録してくれる仕組み。
> 「セーブポイント」を好きなだけ作れるゲームだと思ってください。

できること：

- **いつでも過去の状態に戻せる**（一番大事）
- 「いつ・何を変えたか」がすべて記録される
- 壊しても怖くない → 思い切って改善できる

今回（Phase 1）で、このフォルダを Git 管理下に置き、**現在の状態をセーブポイントとして記録**しました。

### GitHub（ギットハブ）

> **GitHub**… Git の記録を**インターネット上に置いておく場所**。
> ゲームで言えば「クラウドセーブ」。

役割：

- パソコンが壊れても記録が残る
- **Cloudflare Pages が「ここを見て」ホームページを公開してくれる**

**今回は GitHub には一切つないでいません。** Phase 5 で使い始めます。

### Cloudflare Pages（クラウドフレア・ページズ）

> **Cloudflare**… インターネットの高速化とセキュリティを提供する会社。
>
> **Pages**… HTMLファイルを置くと、**世界中に速く配信してくれる**サービス。無料枠で十分足ります。

役割：**GitHub の `index.html` を見張っていて、更新されたら自動で `https://eruremo.com` に反映する。**

```
あなたが「公開」を押す
    ↓
GitHub の index.html が更新される
    ↓
Cloudflare Pages が自動で気づく
    ↓
1〜2分後、https://eruremo.com が新しくなる
```

### Cloudflare R2（アールツー）

> **R2**… **ファイルの倉庫**サービス。写真・動画・PDFなど、何でも置けます。
> Amazon S3 という有名なサービスと同じ仕組みで、**外部への転送料が無料**なのが特徴です。

役割：**写真を置いておく場所。** ここに置いた写真は
`https://images.eruremo.com/media/2026/08/abc123.jpg` のようなURLで読めるようになります。

こうすれば `index.html` には**写真そのものではなく、この住所だけ**を書けばよくなります。

### Cloudflare Worker（ワーカー）

> **Worker**… Cloudflare の上で動く**小さなプログラム**。
> ブラウザとR2やGitHubの「あいだに立つ受付係」だと思ってください。

なぜ必要なのか。**これが今回いちばん大事な考え方です。**

```
❌ 危ないやり方
ブラウザ ──[R2のパスワードを持って]──→ R2
         ↑
    パスワードがHTMLの中にある = 誰でも見られる = 誰でも削除できる

✅ 安全なやり方
ブラウザ ──[写真だけ渡す]──→ Worker ──[パスワードを持って]──→ R2
                              ↑
                    パスワードはここに隠れている = 誰にも見えない
```

Worker がやること：

- 送られてきたファイルが**本当に画像か**を確認する
- **大きすぎないか**を確認する
- **保存する場所（ファイル名）を自分で決める**（利用者に決めさせない）
- R2 に保存して、**公開URLだけ**をブラウザに返す

### Cloudflare Worker Secrets（シークレッツ）

> **Secrets**… **パスワードやトークンを安全にしまっておく金庫**。
> 中身は Worker のプログラムからしか読めず、ブラウザからは絶対に見えません。

ここに入れるもの：GitHub のトークン、その他の秘密の値。

### Cloudflare Access（アクセス）

> **Access**… **管理画面に鍵をかける**仕組み。
> ページを開こうとすると「Googleでログインしてください」と表示され、
> 許可した人以外は中に入れません。

役割：`https://admin.eruremo.com`（将来の管理画面）を守ります。

## 7. APIトークンを HTML に書いてはいけない理由

**これは絶対に守ってください。**

> **APIトークン**（エーピーアイ・トークン）… サービスを操作するための**合鍵**。
> 「このトークンを持っている人＝本人」として扱われます。

### なぜ危ないのか

**ブラウザに送られたものは、全部見られます。例外はありません。**

```
あなたがHTMLに書いたもの
    ↓
ブラウザに送られる
    ↓
誰でも「ページのソースを表示」で読める
誰でも F12 の開発者ツールで読める
誰でも保存して中身を調べられる
```

「JavaScriptの中に隠す」「変数名をわかりにくくする」「Base64にする」
—— **どれも意味がありません。** 全部すぐに読めます。

### 実際に起きること

| 漏れたトークン | 起きること |
|---|---|
| R2 のアクセスキー | **写真を全部消される。** 大量のファイルを置かれて課金が発生する |
| GitHub のトークン | **リポジトリを書き換えられる。** ホームページの内容をすり替えられる |
| Cloudflare の APIトークン | **アカウント全体を操作される。** ドメインを乗っ取られる |

### 正しいやり方

```
❌ ダメ：
   <script>
     const R2_KEY = "abc123...";   ← 世界中に公開されている
   </script>

✅ 正しい：
   ブラウザ側には秘密を一切置かない
        ↓
   「/api/media/upload に画像を送る」だけ
        ↓
   Worker（Secrets に鍵を持っている）が代わりに R2 を操作する
```

### 今回（Phase 1）の状態

**✅ 現在このツールには、APIキー・トークン・パスワードの類は1つも入っていません。**
そもそも外部と通信していないので、完全に安全な状態です。

Phase 2 以降も、この原則を守ります。

## 11. Gitの初期設定（コミットできなかった場合）

Git は「誰が変更したか」を記録するため、**名前とメールアドレス**が必要です。
まだ設定されていない場合は、以下を実行してください。

Zed のターミナル、または PowerShell で：

```powershell
git config --global user.name "あなたのお名前"
git config --global user.email "user@example.invalid"
```

> `--global` は「このパソコン全体で使う設定」という意味です。
> 名前は本名でなくてもかまいません（例：`Eru`）。
>
> ⚠ **メールアドレスは、コミット1つずつに永久に記録されます。**
> GitHub へ公開すると、**誰でもそれを読めます**。ふだん使っているアドレスを
> 書くと、あとから消すには履歴そのものを作り直すしかありません。
>
> そこで **GitHub の「noreply」アドレス**を使ってください。
> GitHub の Settings → Emails に
> `12345678+ユーザー名@users.noreply.github.com` のような形で表示されている、
> **あなた専用の受信できないアドレス**です。これなら本当のアドレスは公開されません。
>
> 上の例に書いてある `user@example.invalid` は、
> **どこにも実在しないと決められている見本用のドメイン**です（そのまま使わないでください）。

設定後、このフォルダで：

```powershell
git add -A
git commit -m "chore: preserve original ERUREMO site manager before refactor"
```

## 13. 困ったときは

| 症状 | 確認すること |
|---|---|
| 編集内容が消えた | `.json` のバックアップから読み込む（メニュー →「📂 プロジェクトを読み込む」） |
| 「保存できません」と出る | 写真が多すぎます。`.json` を書き出してから、写真を減らすか URL方式に変換 |
| プレビューが真っ白 | 「🔄」を押す。それでもダメならF12でエラーを確認 |
